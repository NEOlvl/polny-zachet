# ТЗ: Telegram-бот «Полный зачёт» (версия 1)

Требования к боту, которые действуют сейчас. Любая доработка не должна их нарушать.

Как устроены файлы проекта:

- `SPEC.md` — что бот должен делать и чего не делать. Меняется, только когда меняются сами требования.
- `FIXES.md` — очередь задач на разработку. Сделанные задачи удаляются.
- `STATUS.md` — текущее состояние и шаги владельца (сервер, контент, анонс). Сделанные шаги удаляются.
- `IDEAS.md` — идеи, которых нет в текущей версии. В код не закладываются.

## Цель

Личный чек-лист прохождения GTA 6 с процентом прогресса. Одна функция, любой человек пользуется по ссылке.

Критерий успеха версии: посторонний человек открывает бота, отмечает пункты, закрывает Telegram, возвращается через день — прогресс на месте.

Публичный анонс — когда бот работает на сервере и в `content/` есть хотя бы 2 полностью заполненные категории.

## Чего в этой версии НЕТ

Не делать и не закладывать «на будущее»:

## Стек

- Python 3.12, aiogram 3 (long polling, без вебхуков)
- SQLite через SQLAlchemy 2 (async, aiosqlite), миграции Alembic
- контент игры — YAML-файлы в `content/`, не в базе
- Docker + docker-compose, файл базы в volume
- настройки через `.env` (pydantic-settings): `BOT_TOKEN`, `ADMIN_IDS`, `CHANNEL_URL` (необязательный)
- Pillow для карточки прогресса (шрифт DejaVu Sans в репозитории)
- pytest для логики прогресса и загрузки контента

## Контент

Главное правило: **не выдумывать данные об игре.** Разработчик создаёт только структуру и 2–3 явно тестовых пункта с пометкой `ТЕСТ`. Реальные пункты владелец вносит сам из публичных источников, своими словами (факты брать можно, копировать чужие списки и тексты целиком — нельзя).

Формат `content/<категория>.yaml`:

```yaml
id: collectibles_example        # стабильный, не менять после публикации
title: "Название категории"
order: 10
items:
  - id: col_001                 # стабильный, не менять после публикации
    title: "Название пункта"
    hint: "Короткая подсказка, где искать"   # необязательно
    spoiler: false              # true — название скрыто, пока не нажмёшь
    description: "Подробное описание: где находится, как выполнить"   # необязательно, до 1500 символов
    tips: "Дополнительные советы"                                      # необязательно, до 500 символов
    photo: "AgACAgIAAxkB..."    # необязательно, Telegram file_id картинки; задаётся командой /photo
```

Требования:

- при старте бот валидирует все файлы: уникальность `id` (категорий и пунктов, глобально), обязательные поля, `id` только из `[a-z0-9_]` и не длиннее 24 символов; при ошибке не запускается и пишет, в каком файле и каком пункте проблема
- добавление новых пунктов и категорий не ломает сохранённый прогресс
- удалённый из YAML пункт просто перестаёт показываться и не учитывается в процентах; записи в базе не трогаем
- `description`, `tips`, `photo` необязательны; пункт без них работает как раньше. Неизвестные поля валидатор не отвергает
- команда админа `/reload` перечитывает контент без перезапуска; если новый контент не прошёл валидацию — остаётся старый, админу приходит текст ошибки

## База данных

`users`: `tg_id` (PK), `username`, `first_seen`, `last_seen`, `source`, `notify` (bool, по умолчанию true — согласие на рассылки и уведомления о новых пунктах; у уже существовавших пользователей после миграции true)

`progress`: `tg_id`, `item_id`, `done_at`; уникальная пара (`tg_id`, `item_id`)

`source` — параметр из ссылки `t.me/<бот>?start=<метка>`, записывается один раз при первом входе. Нужен, чтобы видеть, какой чат или пост привёл людей. Метка обрезается до 32 символов, допустимы `[A-Za-z0-9_-]`.

Других таблиц нет. Состояние «спойлер открыт» в базе не хранится (см. ниже).

## Поведение бота

Весь интерфейс — на inline-кнопках, одно сообщение редактируется, а не шлются новые.

1. **`/start`** — короткое приветствие (2–3 строки), дисклеймер, общий процент, кнопки: «Чек-лист», «Мой прогресс», «Поиск», «Канал».
2. **Чек-лист** — список категорий, у каждой счётчик `сделано/всего`.
3. **Категория** — пункты по 8 на страницу, кнопки «назад/вперёд». У каждого пункта одна кнопка с номером и статусом («⬜ n» или «✅ n»); она открывает карточку пункта (п. 12а). Отметить пункт из списка нельзя: отметка ставится и снимается только в карточке. `hint` и кнопка «Ошибка в пункте» под списком не показываются, они есть в карточке. Кнопка-переключатель «Только неотмеченные» / «Показать все»: в режиме фильтра отмеченные пункты не показываются (при перерисовке исчезают, страницы и номера считаются по оставшимся, номер страницы корректируется), счётчик в заголовке остаётся по всей категории; если всё отмечено — «Всё собрано!» и кнопка снять фильтр. Состояние фильтра хранится только во флаге callback_data (в базе его нет), при смене фильтра открывается первая страница. Кнопки из сообщений, отправленных до появления флага, считаются устаревшими («Список обновился»).
4. **Спойлеры.** Пункт со `spoiler: true` показывается как «Скрыто — нажми, чтобы открыть»; первое нажатие на кнопку пункта открывает название, второе открывает карточку (скрытый спойлер карточкой не раскрывается). Открытые пункты хранятся только в текущем сообщении: список открытых id кодируется в callback_data кнопок страницы (или в коротком хэше в памяти процесса). После перезапуска бота или перехода на другую страницу неотмеченные спойлеры снова скрыты — это допустимо. Отмеченный спойлер всегда показывается с названием, нажатие на кнопку сразу открывает карточку.
5. **Мой прогресс** — общий процент, полоска из символов, разбивка по категориям. Кнопка «Поделиться» присылает PNG-карточку (1080×1080): «Полный зачёт», общий процент, полоска и 3 категории с наибольшим процентом (при равенстве выше та, где больше отмечено). На картинке только текст и простые фигуры: никаких логотипов, скриншотов и символики Rockstar/GTA. Подпись — короткий текст и ссылка `t.me/<бот>?start=share` (username из `bot.get_me()`). Картинка рисуется Pillow в `asyncio.to_thread`, шрифт DejaVu Sans лежит в `app/assets/` вместе с файлом лицензии. Не чаще 1 раза в 30 секунд на пользователя, иначе ответ «Карточка уже отправлена выше»; сбой генерации сообщается пользователю и паузу не включает.
6. **Канал** — кнопка-ссылка на `CHANNEL_URL`. Если переменная пустая — кнопки нет.
7. **`/privacy`** — 4–6 строк: какие данные хранятся (Telegram ID, username, отметки прогресса, метка источника, настройка уведомлений; текст сообщения об ошибке в пункте получает администратор и не сохраняется), зачем (работа чек-листа и обезличенная статистика), что данные не передаются третьим лицам, как удалить.
8. **`/delete_me`** — подтверждение кнопкой «Да, удалить», затем удаление записи из `users` и всего прогресса пользователя.
9. **`/find <текст>`** — поиск по названию и подсказке без учёта регистра, «ё» = «е»; все слова запроса должны встретиться. До 8 результатов, по одной кнопке на результат, с отметкой ✅ / ⬜ и названием категории рядом; если нашлось больше — пометка «Показаны первые 8, уточни запрос». Нажатие открывает карточку пункта отдельным сообщением с кнопкой «Закрыть», выдача остаётся прежней (она хранится в памяти процесса по сообщению; после перезапуска бота старые кнопки поиска считаются устаревшими). Отметка из выдачи не ставится: только в карточке. Неотмеченные спойлеры не ищутся (ни по названию, ни по подсказке); отмеченный спойлер находится, а после снятия отметки в выдаче снова скрыт и карточкой не открывается. `/find` без текста и кнопка «Поиск» на главном экране отвечают подсказкой «Напиши /find и слово, например: /find маяк». Текст запроса в логи не пишется.
10. **Меню команд** — при старте бот вызывает `set_my_commands`: `/start`, `/find`, `/privacy`, `/about`, `/delete_me`; админ-команды в общем меню не показываются.
11. **`/notify_off` и `/notify_on`** — пользователь отключает и включает уведомления о новых пунктах и рассылки (`users.notify`). `/privacy` сообщает о настройке и команде `/notify_off`.
12. **Сообщить об ошибке в пункте** — в карточке пункта кнопка «⚠️ Ошибка в пункте». Бот просит одним сообщением описать ошибку (до 1000 символов), есть кнопка «Отмена» (FSM, MemoryStorage). Сообщение пересылается всем админам с id пункта и названием категории (без данных отправителя), пользователь получает «Спасибо, проверим». Любая команда отменяет ожидание; ожидание устаревает через 10 минут и сбрасывается при перезапуске бота. Не больше 3 сообщений в час от одного пользователя (считаются только доставленные). Текст сообщения в логи не пишется. Это не краудсорсинг: пункты пользователи не добавляют, контент исправляет владелец.
12а. **Карточка пункта.** Карточка открывается нажатием на кнопку пункта в списке или в выдаче поиска. Карточка показывает название, категорию, статус (✅ / ⬜), `description`, `hint` и `tips` (что есть), кнопки «Отметить» / «Снять отметку», «⚠️ Ошибка в пункте», «К списку» (возврат на ту же страницу и с тем же фильтром). Без `photo` карточка заменяет текущее сообщение (редактирование). С `photo` карточка присылается отдельным сообщением-фото (подпись до 1024 символов, в конце подписи всегда строка «Фото взято с сайта POWERPYX.COM»; при превышении в подпись идут только заголовок и эта приписка, а описание, подсказка и советы — следующим сообщением; карточка отправляется ответом на сообщение со списком, поэтому отметка из неё обновляет и список), кнопка «Закрыть» удаляет это сообщение вместе со следующим за ним текстом (связь хранится в памяти процесса: после перезапуска бота «Закрыть» удалит только фото); список в исходном сообщении остаётся. Нажатие «Отметить» в карточке меняет статус и в карточке, и в списке (если он на экране). Если у пункта нет ни `description`, ни `tips`, ни `photo`, в карточке написано «Описание пока не добавлено.». Пункт-спойлер открывается в карточке только после раскрытия (как в списке). Из поиска карточка открывается отдельным сообщением с кнопкой «Закрыть», выдача не затирается. Текст описания в логи не пишется.
13. **Обычный текст и неизвестные команды** — ответ «Нажми /start, чтобы открыть чек-лист». Хендлер стоит последним. Админ-команды от не-админов сюда не попадают и остаются без ответа.

### callback_data

- Лимит Telegram — 64 байта. Формат компактный, например `t:col_001:2:0` (действие, id, страница, флаг фильтра «только неотмеченные»).
- Все callback_data собираются и разбираются в одном модуле через aiogram `CallbackData`; тест проверяет, что самая длинная возможная строка ≤ 64 байт.

## Команды админа (только для `ADMIN_IDS`)

- `/stats` — всего пользователей, новых за сутки, активных за сутки и за 7 дней, среднее число отмеченных пунктов, топ-5 категорий по отметкам, число пользователей с отключёнными уведомлениями; активация (доля пользователей хотя бы с 1 отметкой); возвраты (доля пользователей, у которых `last_seen` позже `first_seen` больше чем на 1 сутки и больше чем на 7 суток, среди тех, кто пришёл не меньше 1 и 7 суток назад соответственно); по каждому `source` — пользователей, активных за 7 дней, среднее число отметок; заполнение по категориям (сколько пользователей отметили хотя бы 1 пункт в категории). Считаются только пункты из текущего контента. Длинный отчёт приходит несколькими сообщениями, разделы не рвутся
- `/reload` — перечитать контент
- `/broadcast <текст>` — получатели — только пользователи с `notify = true`; сначала бот присылает предпросмотр и число получателей с кнопками «Отправить» / «Отмена»; после подтверждения рассылает не быстрее 20 сообщений в секунду, обрабатывает `TelegramForbiddenError` (бот заблокирован) и `TelegramRetryAfter` (ждёт и продолжает); в конце — отчёт: доставлено / заблокировали / ошибки. Черновик привязан к своему сообщению предпросмотра: кнопка отправляет именно его текст, повторное нажатие ничего не отправляет («Эта рассылка уже обработана или устарела»)
- `/export` — бот присылает документами архив `content/` и свежую копию базы

- `/notify_new` — уведомление о новых пунктах: бот сравнивает текущий контент со снимком `data/announced_items.json` (id пунктов, о которых уже сообщали) и собирает текст «Новое в чек-листе: Тайники +15, Машины +4» со строкой «Отключить уведомления: /notify_off». Дальше предпросмотр, число получателей (только `notify = true`) и кнопки «Отправить» / «Отмена», механизм рассылки тот же, что у `/broadcast`; под сообщением кнопка «Открыть чек-лист». После отправки снимок обновляется (на состояние контента в момент предпросмотра). Если снимка нет — он создаётся без рассылки («Снимок создан, рассылать нечего»); если новых пунктов нет — «Новых пунктов нет, рассылать нечего»; повреждённый снимок не перезаписывается, админу приходит текст ошибки

Наполнение контента из Telegram (разделитель частей — `|`, пробелы по краям обрезаются):

- `/add <id категории> | <название> | <подсказка> | spoiler` — добавить пункт в конец категории; подсказка и `spoiler` необязательны (пустая подсказка — `-`). `id` пункта генерируется: префикс и сквозная нумерация берутся из id категории (`col_014` → `col_015`), id глобально уникален, после записи не меняется
- `/newcat <id категории> | <название> | <первый пункт>` — создать `content/<id категории>.yaml`, `order` = максимальный существующий + 10; первый пункт обязателен
- `/edit <id пункта> | <название> | <подсказка>` — изменить название и подсказку; без третьей части подсказка остаётся прежней, `-` удаляет её
- `/desc <id пункта> | <описание>` — задать или заменить `description` (до 1500 символов); `-` удаляет. `/tips <id пункта> | <советы>` — то же для `tips` (до 500 символов)
- `/photo <id пункта>` — бот ждёт следующее фото от админа и сохраняет его `file_id` в `photo`; `/photo <id пункта> | -` удаляет картинку. Ожидание устаревает через 10 минут; любая другая команда его отменяет
- `/hide <id пункта>` — убрать пункт из YAML (прогресс в базе не трогаем); последний пункт категории удалить нельзя
- `/cat` — список категорий (id, название, число пунктов, сколько с подсказкой, итог); `/cat <id категории>` — пункты категории с id (🔒 — спойлер, 💬 — есть подсказка, 📝 — есть описание, 🖼 — есть фото). Длинный ответ делится на несколько сообщений

Правила записи: правки пишет `ruamel.yaml` в режиме round-trip (комментарии и порядок полей сохраняются); весь контент сначала валидируется в памяти, при ошибке файл не меняется, а админу приходит текст ошибки; запись атомарная (временный файл + `os.replace`), все команды записи идут под одной блокировкой; после записи контент перечитывается так же, как по `/reload`.

Для обычных пользователей админ-команды молча игнорируются.

## Нефункциональные требования

- любая ошибка в обработчике логируется и не роняет бота
- `last_seen` обновляется middleware на каждое действие
- устаревшие кнопки (после обновления контента) не вызывают исключений: бот отвечает «Список обновился» и показывает актуальное меню
- ошибка `message is not modified` при редактировании подавляется
- логи в stdout, уровень INFO; текст сообщений пользователей в логи не пишется
- оповещения админов (`ADMIN_IDS`): при старте бот пишет «Бот запущен. Контент: N категорий, M пунктов»; записи лога уровня ERROR и выше дублируются в Telegram, одинаковые ошибки — не чаще 1 раза в 5 минут, повторы за это время приходят одной сводкой; текст сообщений пользователей не передаётся; сбой отправки оповещения не роняет бота и не порождает новых оповещений
- секреты только в `.env`, `.env` в `.gitignore`, в репозитории — `.env.example`

## Выкладка

- запуск на VPS (Ubuntu, Docker) по `README.md`, `restart: unless-stopped`, бот поднимается сам после перезагрузки сервера
- реальный контент (`content/*.yaml`, кроме тестового `test_example.yaml`) живёт на сервере и в бэкапах, а не в git: `.gitignore` его исключает, `git pull` его не затирает
- резервные копии — отдельный сервис `backup`: копия базы (`bot-<дата>.db`) и архив папки `content/` (`content-<дата>.tar.gz`) создаются, только если самой свежей такого вида нет или ей 24 часа и больше; проверка раз в час; хранятся 7 последних каждого вида
- обновление на сервере — `scripts/deploy.sh`: `git pull`, пересборка и перезапуск контейнеров, последние 30 строк лога бота
- тесты: `pytest` и `ruff check .` зелёные перед каждой выкладкой; на GitHub их запускает CI (`.github/workflows/tests.yml`) на каждый push и pull request

## Следующие версии

Решения принимаются по `/stats`, а не по ощущениям. Следующая версия, включая монетизацию (Stars, донаты), планируется только после первых живых пользователей.
