# Задачи на разработку

Файл для Devin. Как работать:

- Бери первую задачу со статусом `[ ]`, делай только её.
- Не меняй поведение, которое задача не затрагивает. Требования SPEC.md остаются в силе.
- На каждую задачу — тест. После задачи прогони `pytest`, все тесты должны быть зелёными.
- Когда готово: поставь `[x]`, допиши под задачей строку `Сделано: <что изменено, какие файлы>`, остановись и покажи итог. К следующей задаче переходи только по команде.
- Принятые владельцем задачи удаляются из файла.
- Если задача противоречит SPEC.md или непонятна — не угадывай, спроси.
- Если задача меняет поведение, описанное в SPEC.md, — обнови соответствующий раздел SPEC.md в той же задаче.

Новые задачи добавляются в конец списка.

## 1. [x] Админ-команды для наполнения контента из Telegram

Цель: владелец вносит пункты с телефона, не открывая YAML и не перезапуская бота.

- `/add <category_id> | <название> | <подсказка> | spoiler` — добавить пункт в конец категории. Подсказка и `spoiler` необязательны. Разделитель `|`, пробелы по краям обрезаются.
- `id` пункта генерируется автоматически: уникален глобально, только `[a-z0-9_]`, не длиннее 24 символов, со сквозной нумерацией внутри категории (например, по префиксу уже существующих id категории: `col_014` → `col_015`). Сгенерированный id после записи не меняется.
- `/newcat <category_id> | <название> | <первый пункт>` — создать `content/<category_id>.yaml`, `order` = максимальный существующий + 10. Первый пункт обязателен: категорию без пунктов валидация не пропускает.
- `/edit <item_id> | <название> | <подсказка>` — изменить название и подсказку. Пустая подсказка (`| -`) удаляет её.
- `/hide <item_id>` — удалить пункт из YAML. Прогресс в базе не трогаем (как в SPEC).
- `/cat` — список категорий: id, название, число пунктов, сколько пунктов с подсказкой, общий итог. `/cat <category_id>` — пункты категории с id. Если текст длиннее лимита Telegram — разбить на несколько сообщений.
- Запись YAML через `ruamel.yaml` в режиме round-trip (сохраняет комментарии и порядок полей). Чтение при старте можно оставить на PyYAML.
- Перед записью новый вариант контента валидируется целиком в памяти. При ошибке файл не меняется, админу приходит текст ошибки.
- Запись атомарная: временный файл + `os.replace`. Все команды записи под одним `asyncio.Lock`.
- После успешной записи контент перечитывается так же, как по `/reload`. Ответ: «Добавлено: `<id>` в «<категория>», теперь N пунктов».
- Для не-админов команды молча игнорируются; добавить их в исключения хендлера обычного текста.
- Проверить, что в Docker запись в `content/` (volume) работает.
- Обновить SPEC.md: раздел «Команды админа».

Сделано: `app/content_edit.py` (новый) — `ContentEditor`: `add_item`, `new_category`, `edit_item`, `hide_item`, `generate_item_id`; ruamel round-trip, валидация всего контента в памяти до записи, атомарная запись (`.<имя>.tmp` + `os.replace`). `app/handlers/admin.py` — команды `/add`, `/newcat`, `/edit`, `/hide`, `/cat` (деление длинного ответа на сообщения), общий `asyncio.Lock`, после записи `holder.content` перечитывается; `/reload` теперь читает папку `content_dir`. `app/main.py` — в диспетчер добавлены `content_dir` (по умолчанию `content`) и `content_lock`. `app/handlers/menu.py` — `ADMIN_COMMANDS` (исключения хендлера обычного текста). Обновлены SPEC.md («Команды админа») и README.md. Тесты: `tests/test_content_edit.py`, `tests/test_admin_content.py`; в `tests/test_admin.py` заглушки `load_content` принимают путь. Запись в `content/` через Docker-volume проверена отдельным контейнером на копии папки (боевые контейнеры не перезапускались, их надо пересобрать: `docker compose up -d --build`).
