# Идеи на будущее

Сюда записываем всё, чего нет в ТЗ текущей версии. В код не закладываем.

Этапы ниже — план развития проекта. Этап начинается, только когда выполнено его условие по `/stats`. Тогда его требования переносятся в SPEC.md, а задачи — в FIXES.md. Порядок этапов можно менять по цифрам.

---

## Этап 2. Поддержка проекта через Telegram Stars

**Условие:** не меньше 300 пользователей, и хотя бы 15% возвращаются через 7 дней (метрика из `/stats`).

- Кнопка «Поддержать проект» в `/about` и на экране «Мой прогресс»: донат в Telegram Stars (валюта `XTR`, 3–4 фиксированные суммы).
- Платных функций нет: все пункты и возможности бесплатны, донат — просто благодарность.
- Таблица платежей (id платежа, пользователь, сумма, дата) для учёта и возвратов, команда `/paysupport` (требование Telegram для платежей).
- В `/stats`: число донатов и сумма в Stars.
- Вывод Stars и учёт дохода — по правилам самозанятости (НПД).

## Этап 3. Mini App

**Условие:** пунктов так много, что кнопочный интерфейс неудобен (сотни пунктов в категории или жалобы пользователей), и бот стабильно работает на сервере.

- Веб-интерфейс внутри Telegram: категории, поиск, фильтры, отметки одним касанием, прогресс.
- Бэкенд на FastAPI, авторизация через проверку подписи `initData` от Telegram. База общая с ботом.
- Фронтенд — простой HTML/JS без тяжёлых фреймворков, либо Vite.
- Нужны домен и HTTPS (Caddy или nginx + Let's Encrypt) на том же сервере.
- Бот остаётся: кнопочный интерфейс работает как раньше, Mini App — дополнительная кнопка.
- Вероятно, переход с SQLite на PostgreSQL (два процесса пишут в одну базу).

## Этап 4. Платформа для разных игр

**Условие:** по GTA 6 есть стабильная аудитория, а интерес к ней начинает спадать (новых пользователей за неделю заметно меньше пика).

- Сущность «игра»: контент в `content/<игра>/<категория>.yaml`, выбор игры на главном экране, прогресс по каждой игре отдельно.
- Сохранённый прогресс по GTA 6 не теряется: текущие id пунктов остаются как есть, новые игры получают свои префиксы.
- Следующие игры выбирать по спросу: крупные релизы с большим количеством коллекционных предметов.
- Название «Полный зачёт» не привязано к одной игре, поэтому подходит для платформы без переименования.

## Этап 5. Технический рост

По мере нагрузки, не заранее:

- PostgreSQL вместо SQLite.
- Вебхуки вместо long polling.
- Redis для FSM и кэша.
- Мониторинг: Sentry для ошибок, простые метрики (число запросов, время ответа).

## Отложено, пересматривать только по запросам пользователей

- **Интерактивная карта** — нужны точные координаты, это большой объём ручной работы и риск копирования чужих карт.
- **Пункты от пользователей** — нужна модерация. Вместо этого есть «Сообщить об ошибке» (задача в FIXES.md).
- **Английская версия** — рынок больше, но вдвое больше работы с контентом. Рассматривать вместе с этапом 4.
