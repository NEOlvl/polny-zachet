# Полный зачёт (`@polny_zachet_bot`)

[![tests](https://github.com/NEOlvl/polny-zachet/actions/workflows/tests.yml/badge.svg)](https://github.com/NEOlvl/polny-zachet/actions/workflows/tests.yml)

Telegram-бот: личный чек-лист 100% прохождения GTA 6 с процентом прогресса.
Неофициальный фан-проект. Не связан с Rockstar Games и Take-Two Interactive.

Стек: Python 3.12, aiogram 3 (long polling), SQLite + SQLAlchemy 2 + Alembic, YAML-контент, Docker Compose.

## Настройки (`.env`)

| Переменная    | Что это                                              |
|---------------|------------------------------------------------------|
| `BOT_TOKEN`   | токен от @BotFather                                  |
| `ADMIN_IDS`   | Telegram ID админов через запятую (узнать: @userinfobot) |
| `CHANNEL_URL` | ссылка на канал; пусто — кнопки «Канал» не будет     |
| `MINIAPP_URL` | https-адрес Mini App; пусто — веб-часть выключена    |
| `MINIAPP_PORT` | порт веб-сервера Mini App (по умолчанию 8000)       |
| `DEV_TG_ID`   | обход авторизации Mini App — только локальная разработка |

Шаблон — `.env.example`. Файл `.env` в репозиторий не попадает.

## Запуск локально

```bash
cp .env.example .env      # вписать BOT_TOKEN и ADMIN_IDS
docker compose up -d --build
docker compose logs -f bot
```

Тесты (нужен Python 3.12):

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest
.venv/bin/python -m ruff check .      # стиль и типичные ошибки (конфиг — ruff.toml)
```

На GitHub те же две проверки (`ruff` и `pytest`) запускает CI на каждый push и pull request: `.github/workflows/tests.yml`. Локально перед коммитом достаточно выполнить обе команды (на Windows — `.venv\Scripts\python`).

## Выкладка на VPS (Ubuntu + Docker)

1. **Docker.** Установить Docker Engine и плагин Compose по [официальной инструкции](https://docs.docker.com/engine/install/ubuntu/) и убедиться, что он стартует вместе с системой:
   ```bash
   sudo systemctl enable --now docker
   ```
2. **Код.** Скопировать проект на сервер (git clone или `scp -r`) и перейти в папку:
   ```bash
   cd polny-zachet
   ```
3. **Настройки.**
   ```bash
   cp .env.example .env
   nano .env      # BOT_TOKEN, ADMIN_IDS, при желании CHANNEL_URL
   chmod 600 .env
   ```
4. **Запуск.**
   ```bash
   docker compose up -d --build
   docker compose logs --tail 20 bot
   ```
   В логах должно быть `Контент загружен` и `Run polling for bot @polny_zachet_bot`.
   Миграции базы применяются автоматически при старте контейнера.
5. **Проверка перезагрузки сервера.**
   ```bash
   sudo reboot
   ```
   После загрузки (1–2 минуты) подключиться снова и выполнить `docker compose ps` — оба контейнера (`bot` и `backup`) в состоянии `Up`. Отправить боту `/start`: прогресс на месте.
   Контейнеры поднимаются сами благодаря `restart: unless-stopped` и автозапуску Docker из шага 1.

Порты открывать не нужно: бот сам ходит в Telegram (long polling), вебхуков нет.

## Обновление

На сервере:

```bash
bash scripts/deploy.sh
```

Скрипт делает `git pull --ff-only`, `docker compose up -d --build` и показывает последние 30 строк лога бота. Контент и база (`content/`, `data/`) при этом не затрагиваются. Без git — скопировать новые файлы и выполнить `docker compose up -d --build`.

База (`data/bot.db`) лежит в папке `data/` на сервере и при пересборке сохраняется.

## Контент

Категории и пункты — YAML-файлы в `content/` (формат описан в `SPEC.md`). Папка подключена к контейнеру, поэтому пересборка не нужна:

Основной способ — админ-команды `/add`, `/newcat`, `/edit`, `/hide` (пример: `/add col | Название пункта | Где искать`; список — `/cat`). Бот сам пишет файлы в `content/` и перечитывает контент. Файлы, созданные ботом, принадлежат root (контейнер работает от root): править их руками на сервере нужно через `sudo`.

Ручная правка YAML тоже работает:

1. Отредактировать файлы в `content/` на сервере.
2. Отправить боту `/reload` (команда только для админов).
   Если файлы не прошли проверку, остаётся прежний контент, а в ответе будет описание ошибки.

`id` категорий и пунктов после публикации менять нельзя — по ним хранится прогресс пользователей. Удалённый из YAML пункт перестаёт показываться и считаться в процентах; записи в базе не трогаются.

**Где живёт контент.** Реальные файлы `content/*.yaml` (кроме тестового `test_example.yaml`) не лежат в git: они в `.gitignore`. Источник правды — папка `content/` на сервере и её бэкапы, поэтому `git pull` контент не затирает. Не удаляйте `content/` на сервере и скачивайте архивы (см. «Резервные копии»).

Тестовую категорию `content/test_example.yaml` (пункты с пометкой «ТЕСТ») перед публичным анонсом нужно удалить.

## Mini App

Веб-версия чек-листа внутри Telegram — кнопка «Открыть чек-лист» на `/start` (появляется при заданном `MINIAPP_URL`). Требования — `docs/MINIAPP_SPEC.md`. FastAPI поднимается в том же процессе, что и бот; база и контент общие.

### Проверка локально (без сервера и домена)

1. Поднять туннель до порта Mini App (аккаунт не нужен):
   ```bash
   cloudflared tunnel --url http://localhost:8000   # или: ngrok http 8000
   ```
2. Полученный `https://<случайный>.trycloudflare.com` вписать в `.env`: `MINIAPP_URL=...`
3. `docker compose up -d --build bot` — кнопка появится на `/start`. Порт публикуется только на localhost (`127.0.0.1:8000`), наружу не светится.

Адрес туннеля временный: после его перезапуска повторить шаги 1–3.

### Выкладка на сервере

1. Домен + A-запись на IP сервера (например `app.example.com`).
2. В `.env` на сервере: `MINIAPP_URL=https://<домен>` (без слэша в конце).
3. `docker compose --profile miniapp up -d` — поднимется сервис `caddy`, он сам получит сертификат Let's Encrypt (нужны открытые порты 80 и 443). `scripts/deploy.sh` включает профиль автоматически, когда в `.env` задан `MINIAPP_URL`.
4. Проверка: `https://<домен>` в обычном браузере покажет ошибку «открой через кнопку в боте» — это нормально (нет `initData`). Рабочий вход — кнопка «Открыть чек-лист» в боте.
5. BotFather: web_app-кнопке регистрация не нужна. По желанию — Menu Button через `/setmenubutton`.

## Карточка прогресса

Кнопка «Поделиться» на экране «Мой прогресс» присылает картинку-карточку. Она рисуется библиотекой Pillow (есть в `requirements.txt`, в Docker ставится при сборке) шрифтом DejaVu Sans из `app/assets/`; лицензия шрифта — `app/assets/DejaVu-LICENSE.txt`. Ссылка в подписи ведёт на бота с меткой `share` (видна в `/stats`).

## Сообщения об ошибках в пунктах

В карточке пункта у пользователей есть кнопка «⚠️ Ошибка в пункте». Описание приходит всем админам из `ADMIN_IDS` вида «⚠️ Ошибка в пункте / Пункт: <id> — название / Категория: …» и текст. Исправить пункт можно командой `/edit <id> | <название> | <подсказка>`. Не больше 3 сообщений в час от одного пользователя. Тексты сообщений бот нигде не сохраняет и в логи не пишет.

## Оповещения админов

Админы из `ADMIN_IDS` получают сообщение при каждом запуске бота («Бот запущен. Контент: N категорий, M пунктов») и копии ошибок из логов (уровень ERROR и выше). Одинаковая ошибка приходит не чаще раза в 5 минут, повторы за это время — одной сводкой. Если после перезагрузки сервера сообщения «Бот запущен» нет, значит бот не поднялся: `docker compose logs --tail 50 bot`. Чтобы бот мог писать админу, админ должен хотя бы раз нажать `/start`.

## Команды админа

- `/stats` — пользователи, активность, активация и возвраты (1 и 7 суток), источники (пользователи, активные за 7 дней, среднее число отметок), топ-5 категорий, заполнение по категориям, число отключивших уведомления
- `/reload` — перечитать контент
- `/add`, `/newcat`, `/edit`, `/hide`, `/cat` — наполнение контента прямо из Telegram (формат команд — в `SPEC.md`): пункт добавляется в YAML и сразу появляется у пользователей, `/reload` после этого не нужен
- `/desc <id пункта> | <описание>`, `/tips <id пункта> | <советы>` — описание (до 1500 символов) и советы (до 500) для карточки пункта, `-` удаляет. `/photo <id пункта>` — затем прислать фото (бот сохранит его `file_id`), `/photo <id пункта> | -` удаляет. `/cat <категория>` помечает пункты: 📝 есть описание, 🖼 есть фото
- `/export` — бот присылает архив `content/` и свежую копию базы документами (удобно скачать бэкап с телефона)
- `/broadcast <текст>` — рассылка: сначала предпросмотр и число получателей, отправка только после кнопки «Отправить». Получают её только те, у кого включены уведомления (`/notify_on`, по умолчанию включены)
- `/notify_new` — уведомление о новых пунктах («Новое в чек-листе: Тайники +15…»). Бот сравнивает контент со снимком `data/announced_items.json`; при первом вызове снимок просто создаётся. Рекомендуемый порядок: наполнить контент → `/notify_new` → проверить предпросмотр → «Отправить». Снимок лежит в `data/` и попадает в бэкапы вместе с базой

Ссылка с меткой источника: `https://t.me/polny_zachet_bot?start=<метка>` (до 32 символов, `A–Z a–z 0–9 _ -`). Метка видна в `/stats`.

## Резервные копии

Сервис `backup` проверяет раз в час, нужны ли копии. Копия базы и архив папки `content/` создаются, если самой свежей такого вида нет или ей 24 часа и больше (при старте проверка тоже выполняется, но перезапуски лишних копий не плодят). Файлы лежат в `data/backups/`: `bot-ГГГГММДД-ЧЧММСС.db` и `content-ГГГГММДД-ЧЧММСС.tar.gz` (время UTC), каждого вида хранятся 7 последних.

Восстановление:

```bash
docker compose stop bot
cp data/backups/bot-<нужная>.db data/bot.db
docker compose start bot
```

Восстановление контента из архива (внутри лежит папка `content/`):

```bash
tar -xzf data/backups/content-<нужная>.tar.gz     # перезапишет файлы в content/
```
После этого отправьте боту `/reload`.

Копии лежат на том же диске, что и база. От потери сервера они не защищают — периодически скачивайте `data/backups/` к себе:

```bash
scp -r user@server:~/polny-zachet/data/backups ./backups
```

```bash
docker compose ps                 # состояние
docker compose logs -f bot        # логи бота
docker compose restart bot        # перезапуск
docker compose down               # остановка (данные в data/ сохраняются)
```
